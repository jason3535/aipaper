摘要 · Abstract

本文介绍《战斗无人机》（Battle Drones）——一款几乎完全借助 Claude Code 等编程智能体、以氛围编程方式构建的浏览器即时战略游戏，并记录了它在十二个主要迭代版本中的演进过程。作者几乎没有游戏开发经验，通过“让它好玩得多”“增加视觉打磨”之类的提示词驱动智能体，最终产出了 3D 模型、多张地图与生物群系、性格各异的 AI、智能体对智能体的对战，以及一个名为 Goliath 的巨型机甲单位。本文的核心论点是：编程智能体如今已能构建不仅视觉上令人信服、而且真正好玩的游戏，这推翻了作者此前认为它们只能做出“看起来像游戏”的东西的看法。一个值得注意的特性是附近设备之间通过音频消息同步的多人模式，它无需运行服务器，并使游戏保持为静态 HTML。作者总结道：氛围编程游戏被认真对待的道路已经出现，而静态 Web 技术加上能力强大的模型，构成了一种极具吸引力的游戏开发媒介。

This article describes Battle Drones, a browser-based real-time strategy game built almost entirely through vibe coding with coding agents such as Claude Code, and documents its evolution across twelve major iterations. The author, who has little game development experience, used prompts like "Make it a LOT more fun" and "add visual polish" to drive the agents, which produced 3D models, multiple maps and biomes, varied AI personalities, agent-versus-agent battles, and a giant mech unit called the Goliath. The core argument is that coding agents can now build games that are not only visually convincing but genuinely fun to play, contradicting the author's earlier belief that they could only produce things that look like games. A notable feature is multiplayer between nearby devices synchronized through audio messages, which avoids running a server and keeps the game as static HTML. The author concludes that a path now exists for vibe coded games to be taken seriously, and that static web technologies plus capable models make a compelling medium for game development.

  • 趣味性与打磨程度由单一作者主观判断，缺乏正式用户研究或评估。
    Fun and polish were judged subjectively by one author; no formal user study or evaluation.

战斗无人机——一款以氛围编程打造的、基于音频多人的即时战略游戏 Battle Drones—a vibe coded RTS with audio-based multiplayer

我最新的氛围编程游戏实验是一款《命令与征服》风格的 RTS（即时战略）游戏，名为 Battle Drones（可在此处游玩）。与我之前的实验不同，这一款**玩起来确实有趣**。我有点不好意思承认，我是靠告诉 Claude“让它有趣得多”才做到这一点的。它还支持附近设备之间通过音频同步游戏状态来进行多人对战！以下是我目前构建的内容，以及在此过程中学到的一些东西。

My latest vibe coded game experiment is a Command & Conquer style RTS (Real Time Strategy) game called Battle Drones (play it here). Unlike my previous experiments, this one is _actually fun to play_. I'm somewhat embarrassed to admit that I got there by telling Claude to "Make it a LOT more fun". It also supports multiplayer between nearby devices using audio to synchronize game state! Here's what I've built so far, and some of the things I learned along the way.

战斗无人机 Battle Drones

我最初的目标是构建一款我可以在手机上玩的 RTS 游戏，风格类似于《命令与征服》。我对 1995 年的原版游戏有着美好的回忆（我也喜欢《红色警戒》），并希望重新捕捉到一点那种魔力。

My initial goal was to build an RTS game I could play on my phone, in the style of Command & Conquer. I have fond memories of the 1995 original (I liked Red Alert too) and wanted to recapture a little bit of the magic.

经过 12 次重大迭代（以及由编码智能体（主要是 Claude Code）完成的 321 次提交），我现在有了一个基于浏览器的游戏，它可以在移动端和桌面端运行，有多种游戏模式、几张地图（包括随机地图生成器），甚至支持两台设备在彼此麦克风范围内的多人游戏。（更新：也支持在线多人游戏；音频多人游戏引发了头痛！）

After 12 major iterations (and 321 commits by coding agents, mainly Claude Code) I now have a browser-based game that works on mobile and desktop, has multiple play modes, several maps (including a random map generator) and even supports multiplayer for two devices within microphone range of each other. (Update: also online multiplayer; the audio multiplayer induced headaches!)

我是如何构建它的 How I built this

Battle Drones 在很大程度上是“氛围编程”（vibe coding）的产物——我几乎没有审查过其中的代码，而且它是用一种我本人几乎没用过的语言（TypeScript）构建的。不过我对其进行了相当多的试玩测试，并且自项目启动以来，它已经经历了大量迭代。

Battle Drones is heavily vibe coded—I've reviewed almost none of the code, and it's built in a language (TypeScript) that I've hardly used myself. I've playtested it quite a bit though, and it's been through a large number of iterations since I started the project.

以下是该项目迄今为止的大致历程，包括关键提示词（prompts）和对话记录（transcripts）的链接。

v4：趣味升级 v4: the fun update

到目前为止，我的 Battle Drones 实验印证了我先前的看法：编程智能体能够造出一个看起来像游戏的东西，却无法真正做出让人玩起来欲罢不能的作品。

So far my Battle Drones experiment was confirming my previous belief that coding agents can build a thing that looks like a game but can't actually make something that's genuinely compelling to play.

我在一次晚餐时把这个观点讲给某人听，随后心想，我应该给这些模型一个正经的机会来证明我错了。我在手机上向 Opus 5.5 输入了提示词：

I shared this theory with someone over dinner, and then thought to myself that I should give the models a proper chance to prove me wrong. I prompted Opus 5.5 on my phone:

这个游戏还不够好玩。让它变得**好玩得多**。

This game isn't fun enough yet. Make it a LOT more fun.

这一次我运行在 Ultracode 模式下，在该模式下 Claude Code（此处为 Claude Code for Web）会运行“动态工作流”，其文档中的描述是：

This time I was running in Ultracode mode, where Claude Code (in this case Claude Code for Web) runs "dynamic workflows", described in their docs as:

这开启了 _数小时_ 的工作。我晚上开始，直到第二天凌晨才得到可玩的结果。但结果非常壮观。

v8：群岛 v8: Archipelago

我开始感到内疚，因为我对游戏的实际设计投入太少了——过去几个版本真的就是我说“让它更有趣”和“增加视觉打磨”。

I was beginning to feel guilty at how little actual design input I had into the game—it really had been a case of me saying “make it more fun” and “add visual polish” for the past few releases.

我注意到 AI 并不经常使用 v7 中新增的步兵和运兵飞机——并没有很好的战略理由去使用它们。

It would be neat if we had a new map with a new game mechanic that actively encouraged players to load up Condors with infantry robots and send them out into the map.

设计一张新地图。目标是创造不同的战略激励，鼓励使用步兵、秃鹰和空中载具。

Design a new map. Goal is to make different strategic incentives that encourage use of Infantry and Condors and aerial vehicles.

为此，地图将拥有有限的收割机资源，但会有更多上行链路——不过上行链路将位于陆地载具或步兵无法到达的岛屿上。这些上行链路也不能用空中载具占领。获得它们的唯一方法是用秃鹰将步兵空运到那里。

To do this the map will have limited harvester resources but several more uplinks - but uplinks will be on islands that are inaccessible by land vehicles or infantry. These uplinks can also not be claimed using air vehicles. The ONLY way to get them is to fly infantry there in a Condor.

Armies always start with a Condor and a single squad. If an army has no Condor, a new one will be provided for free, flying in from the edge closest to their HQ and landing there. That free Condor will come with a single free squad on board.

两个 HQ 应完全被水域隔开，但仍可通过地图上不同位置的两座桥梁供车辆通行。

The two HQs should be entirely separated by water, but still accessible by vehicles thanks to two bridges across the map in different places.

我希望鼓励围绕上行链路（uplink）展开争夺战。

I want to encourage a battle over uplinks.

The map should be three times the size of other maps — still square.

有趣的额外挑战：想一想我们怎样才能让编程智能体也能参与多人对战。如果我们能安排一场例如 GPT-6 Sol 与 Claude Opus 5.5 之间的对战，那就太棒了——每个模型都能访问一个工具，该工具为它提供游戏信息（大概是非视觉的，只包含它通过战争迷雾等能看到的信息），并让它控制自己的单位等 [...]

I only _just_ got this working, so I've not had much time to actively test it yet. The latest Battle Drones now supports multiplayer via two devices sat within microphone distance of each other!

这个功能最初源于我上周的 Chirp Pong 实验。我把 Claude Code 指向那个可用的概念验证：

Opus 构建了这个 Radio Probe 工具，用来测量两台设备之间能获得多大带宽；基于该工具得到的积极结果，它实现了一套完整的音频调制解调器系统。到目前为止，我已经在笔记本电脑、iPhone 和 iPad 之间试过，效果似乎非常好！

Why use sound for this? Because I love static HTML that costs nothing to run, and I don't want to spin up a server somewhere and then stay responsible for keeping it operating for as long as anyone might want to play the game.

一些思考 Some thoughts

我对游戏开发几乎**一无所知**。这反而成了一个绝佳机会：在一个我已有的软件工程经验对结果影响较小的领域里，试用编码智能体。

I know almost _nothing_ about game development. This makes it a great opportunity to try out coding agents in a field where my existing software engineering experience has less impact on the results.

游戏本身也风险极低。最坏的情况也不过是我某个愚蠢的游戏实验出了个 bug。

Games are also super low stakes. The worst that can happen is one of my silly game experiments suffers a bug.

今天早上（通过 Hacker News）我看到一篇文章《Steam 玩家恳求推出无 AI 过滤器，因为 Steam Next Fest 充斥着粗制滥造之作》。我个人绝不会想把 Battle Drones 提交到这样的活动——它仍然太过粗糙，不足以被视为一个正经的独立游戏项目。

This morning (via Hacker News) I found "Steam Fans Are Begging for a No-AI Filter as Steam Next Fest Is Filled With Slop". I wouldn't personally dream of submitting Battle Drones to an event like this—it's still way too low effort to warrant consideration as a legitimate indie gaming project.

……但我现在能看到一条路径，让这类“凭感觉编码”（vibe coded）的游戏被认真对待。Battle Drones 很好玩，画面不错，还有创新特性（据我所知，通过音频实现多人联机在 RTS 中尚属首次）。

... but I can now see a path to vibe coded games like this being taken seriously. Battle Drones is fun, it looks good, it has innovative features (the multiplayer-over-audio thing is a first for an RTS as far as I can tell).

我很想看看，一个比我更有品味、并且有强烈热情去打造真正卓越作品的人，能做出什么样的东西！

I'd love to see what someone with better taste than me and a driving passion to produce something truly exceptional could build!

关于这个项目，还有几点其他观察：

A few other observations from this project:

* 静态 HTML 和 JavaScript 是游戏开发的绝佳媒介。WebGL 运行良好，而 Three.js（以及更早的 Phaser）是极佳的构建平台，当前的模型对它们了如指掌。

* Static HTML and JavaScript is a fantastic medium for games development. WebGL works great, and Three.js (and Phaser before it) are excellent platforms to build on that the current models know inside out.

* 这也让它们能够以渐进式 Web 应用（Progressive Web App）的形式运行——我并没有要求这一点，但 Battle Drones 可以离线运行。尽管我从未直接安装过它，却能在飞机上玩它——我的手机已经缓存了它。

* This also lets them run as Progressive Web Apps—I didn’t ask for it, but Battle Drones works offline. I was able to play it on a plane despite never having directly installed it—my phone had it cached.

* 给 Claude 一个 OpenAI API 密钥，并让它使用 OpenAI 的模型生成图像，效果非常好。它能够查看自己生成的图像，并据此迭代提示词。

* Giving Claude an OpenAI API key and telling it to generate images using OpenAI’s models works really well. It can view the images it has generated and iterate on the prompts.

* Opus 5.5 在使用 Three.js 进行 3D 建模方面表现出色（在 Blender 中也是如此，无疑在其他 3D 应用中同样如此）。GPT-6 Astra 也是如此。它们完全有能力为 3D 游戏项目构建模型。

* Opus 5.5 is spectacular at 3D modeling using Three.js (and Blender, and no doubt other 3D applications as well). The same is true of GPT-6 Astra. They are absolutely capable of building models for 3D game projects.

* 对于回放和多人游戏等功能，拥有一个确定性的模拟引擎是很有用的。有一次，Claude 不得不将 Math.sin() 和 Math.cos() 等函数的调用替换为自定义版本，因为不同的浏览器（例如 Chrome 与 Safari）返回的数值略有不同，导致回放不同步。

* For features like replay and multiplayer it’s useful to have a deterministic simulation engine. At one point Claude had to replace calls to Math.sin() and Math.cos() and friends with custom versions because different browsers (Chrome vs. Safari, for example) returned very slightly different numbers, desynchronizing the replay.

* Opus 5.5 可以创作音乐！这个项目中没有音频文件——配乐完全通过代码生成，在不同地图中有所变化，甚至随着战斗升温而变得更加激烈。参见 Scrimshaw Jukebox，这是之前用 Claude 进行音乐创作的一个实验。

* Opus 5.5 can write music! There are no audio files in this project—the soundtrack is entirely generated through code, varies across different maps, and even gets more intense as the battle heats up. See Scrimshaw Jukebox for a previous experiment with Claude for music composition.

* 我仍然无法释怀“让它变得有趣得多”这个提示词的效果有多好。

* I still can’t get over how well the prompt “Make it a LOT more fun” worked.

* 工具实际上是免费的。我提示构建了 Radio Probe、模型浏览器、Agent vs. Agent 调试工具，而 Claude Code 为自己构建了一堆我甚至还没探索过的工具。

* Tools are effectively free. I prompted up the Radio Probe, the Model browser, the Agent vs. Agent debug tool, and Claude Code built a bunch of tools for itself that I haven’t even explored myself.

* 静态 HTML 游戏之间基于音频的多人游戏是可行的！我希望看到更多游戏使用这种相同的模式——今天在挖掘过程中，除了 Alon Horesh 的 Siner 和 Georgi Gerganov（也是 llama.cpp 的成名者）的 ggwave 之外，我没有发现太多先例。

* Audio-based multiplayer between static HTML games works! I hope to see a whole lot more games use this same pattern—in digging around today I’ve not found much prior art beyond Siner by Alon Horesh and ggwave by Georgi Gerganov (also of llama.cpp fame).

* Claude Code 的“Ultracode”模式消耗 token 如同没有明天，但它也能仅凭一条提示词就解决复杂问题（比如加入基于音频的多人模式）。

* Claude Code "Ultracode" burns tokens like there's no tomorrow, but it can also solve complex problems (like adding audio-based multiplayer) from a single prompt.

* 我至今仍未能完全摆脱以这种方式构建软件的_负罪感_。在一个我此前经验如此之少的领域里，我并不觉得自己有资格创造出如此出色的东西！事到如今，我已经私下把它展示给了足够多的人，若再不公开发布、让其他人也能看到并从中学习，反倒显得不妥了。

* I'm still not quite over the _guilt_ of building software in this way. I don't feel like I've earned the right to create something this good, in a field in which I have so little prior experience! At this point I've shown it to enough people in private that it felt wrong not to publish it for everyone else to see and learn from.

更新：在线多人支持 Update: Online multiplayer support

游戏的风险也极低。最坏的情况也不过是我某个傻乎乎的游戏实验出了个 bug。

Games are also super low stakes. The worst that can happen is one of my silly game experiments suffers a bug.

然后我试着和 Natalie 一起玩多人版本……结果那尖锐的调制解调器音效让她头痛得厉害！

这算是个挺严重的 bug。我加了一条警告，随后受到启发，决定构建真正的网络多人功能。我尝试让 WebRTC 跑起来，但即便在我自己的 WiFi 网络上，也无法在我自己的两台设备之间建立连接，于是我让 Claude 改为构建一个简单的、无状态的 WebSockets 中继服务器：

That's a pretty bad bug. I added a warning and was then inspired to build proper network multiplayer. I tried getting WebRTC to work but couldn't get a connection going between two of my own devices even on my own WiFi network, so I had Claude build a simple, stateless WebSockets relay server instead:

如果我想以极低的成本在两台设备之间支持多人游戏，且不在服务器上存储任何状态，我能否用一个运行在最便宜 Fly 实例上的小型 asyncio Web 服务器来实现？

If I wanted to support multiplayer between two devices at a very low cost without storing any state on the server, could I do that with a tiny asyncio web server running on the cheapest Fly instance?

构建该服务器以及用于部署的 fly.toml。使用 Fly 应用名 battledrones-relay——把它放在仓库中的一个文件夹里，并在该文件夹的 README 中包含部署说明。

Build the server and the fly.toml for deploying it. Use the Fly application name battledrones-relay — put that in a folder in the repo, and include deploy instructions in the README in that folder.

这是最终得到的服务器。由于它可以缩容到零，并且运行在单个 Fly.io shared-cpu-1x 实例上，我的花费应该不超过每月 2.19 美元——而且这还是假设它全程保持热启动并持续处理连接的情况。

Here's the resulting server. Since this scales to zero and runs on a single Fly.io shared-cpu-1x instance, it should cost me no more than $2.19/month—and that's if it stays hot and serving connections the whole time.

Battle Drones 现已支持在线多人对战。点击“Duel a friend online”，然后通过你常用的消息应用分享生成的房间 URL，或者让对方拍下所显示的二维码。

Battle Drones now supports online multiplayer. Click "Duel a friend online", then either share the resulting room URL via your messaging app of choice or have them snap a picture of the displayed QR Code.

我还添加了一项功能：对局结束后，你可以复制该对局的 JSON，再将其输入回放功能，以重新观看你的比赛。

I also added a feature where you can copy the JSON of the match once it has ended and then feed that into the replay feature to rewatch your game.

我没想到会这么早引入在线多人对战，但那个令人头疼的 bug 让我觉得有必要尽快提供一个替代方案。

I didn't expect to introduce online multiplayer this soon, but the headache bug felt like it warranted an urgent alternative.
