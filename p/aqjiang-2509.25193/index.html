摘要 · Abstract

我们推出了 Devstral-Small，一个轻量级的开源代码智能体模型，在 100B 以下规模的模型中表现最佳。本技术报告概述了我们如何设计和开发模型，并在智能体软件开发中打造专业化能力。最终得到的 Devstral-Small 是一个仅有 24B 参数的小模型，快速且易于部署。尽管规模小，Devstral-Small 在与大一个数量级以上的模型相比时，仍能取得有竞争力的性能。

We introduce Devstral-Small, a lightweight open source model for code agents with the best performance among models below 100B size. In this technical report, we give an overview of how we design and develop a model and craft specializations in agentic software development. The resulting model, Devstral-Small is a small 24B model, fast and easy to serve. Despite its size, Devstral-Small still attains competitive performance compared to models more than an order of magnitude larger.

  • 提出 Devstral-Small，一个 24B 的开源模型，专为代码智能体任务设计，在 100B 以下模型中达到最优性能。

    Proposes a two-stage training pipeline combining supervised fine-tuning on agent trajectories and policy optimization.
  • 开发了迭代评估协议，最多 3 次尝试并调度温度，以稳健测量智能体性能。
    Develops an iterative evaluation protocol with up to 3 attempts and temperature scheduling for robust agent performance measurement.
  • 证明专用代码智能体模型在软件工程任务上可超越更大的通用模型。
    Demonstrates that specialized code agent models can outperform much larger general models on software engineering tasks.

    Training data limited to SWE-Gym trajectories; coverage of diverse software engineering scenarios is not guaranteed.

1 引言 1 Introduction

大型语言模型（LLMs）越来越多地被应用于代码相关任务，在生成、理解和补全代码方面展现出卓越的能力（Austin 等人，2021；Chen 等人，2021；OpenAI，2025；Anthropic，2025）。一些高性能的开源代码补全模型——例如 CodeLlama（Roziere 等人，2023）、Qwen 2.5 Coder（Hui 等人，2024）或 Codestral（Mistral AI，2025）——已发布用于代码补全和生成任务。

Large language models (LLMs) have been increasingly adapted for code-related tasks, demonstrating remarkable capabilities in generating, understanding, and completing code (Austin et al., 2021; Chen et al., 2021; OpenAI, 2025; Anthropic, 2025). Several high-performance open code completion models—such as CodeLlama (Roziere et al., 2023), Qwen 2.5 Coder (Hui et al., 2024) or Codestral (Mistral AI, 2025)—were released for code completion and generation tasks.

在过去一年中，编码智能体作为 LLM 代码模型的一种独特且新颖的应用出现（Cognition AI，2025；Yang 等人，2024；Wang 等人，2025）：将 LLM 集成到基于智能体的系统中，为自动化复杂的软件工程工作流程开辟了新途径，例如解决问题、执行重构或实现涉及代码库中多个文件的特性。然而，智能体式编码具有挑战性；前几代模型擅长生成语法正确的代码，但往往难以处理需要针对项目特定上下文或外部工具进行推理的复杂多步编程任务。尽管闭源模型取得了显著进展（Anthropic，2025；OpenAI，2025），但开源模型仍然缺乏迭代开发过程所需的智能体能力，例如调试或与软件工具集成。因此，代码智能体主要使用闭源模型，如 Claude（Anthropic，2025）。

In the past year, the coding agent has emerged as a unique and novel application of LLM code LLMs (Cognition AI, 2025; Yang et al., 2024; Wang et al., 2025): the integration of LLMs into agent-based systems has opened new avenues for automating complex software engineering workflows, such as solving issues, performing refactors or implementing features involving several files in a codebase. Agentic coding is, however, challenging; previous generations of models excel in generating syntactically correct code but often struggle with complex, multi-step programming tasks that require reasoning over project-specific contexts or external tools. Although closed models have made significant progress Anthropic (2025); OpenAI (2025), open models still lack the agentic capabilities needed for iterative development processes, such as debugging or integrating with software tools. Hence, code agents use mainly closed models such as Claude (Anthropic, 2025).

针对这一差距，我们推出了 Devstral-Small，一个专为代码智能体应用而设计的 24B 模型。通过融入智能体式推理，Devstral-Small 具备了与开发环境交互并更有效地处理多步任务的能力。尽管只有 24B 参数，Devstral-Small 在代码智能体任务中仍是一个高性能模型。

Addressing this gap, we introduce Devstral-Small, a 24B model specialized for code agent applications. By incorporating agentic reasoning, Devstral-Small possess the capabilities to interact with development environments and handle multi-step tasks more effectively. Despite having only 24B parameters, Devstral-Small is a high-performing model for agentic tasks for code.

2.1 基础模型 2.1 Base Model

Devstral-Small 是一个密集 Transformer，总参数量为 240 亿。它基于 Mistral Small 3，具有 40 层，并使用分组查询注意力机制。该模型在包括自然语言和代码在内的多种文本来源上进行了预训练。一个长上下文扩展阶段将模型上下文大小提升至 128k 个词元，适用于代码智能体和其他长上下文任务。

Devstral-Small is a dense Transformer consisting of a total of 24 billion parameters. It is based on Mistral Small 3, has 40 layers and uses grouped query attention. The model is pre-trained on diverse sources of text including both natural language and code. A long context extension phase boosts the model context size to 128k tokens suitable for code agent and other long context tasks.

2.2 数据 2.2 Data

对于代码智能体，我们希望培养一种交互模式，其中智能体以及底层模型在思维链（Wei 等人，2022）推理和编码环境中的操作之间交替，以执行软件工程任务。我们通过在 SWE-Gym 环境（Pan 等人，2024）中使用 OpenHands CodeAct 脚手架（Wang 等人，2025，2024）运行智能体来生成监督轨迹。我们执行单元测试以确定最终补丁的质量。

For code agents, we want to foster an interaction pattern in which the agent, and consequently the underlying model, alternates between chain-of-thought (Wei et al., 2022) reasoning and actions within the coding environment to perform the software engineering task. We generate supervised trajectories by running an agent in the SWE-Gym environments (Pan et al., 2024) with the OpenHands CodeAct scaffold (Wang et al., 2025, 2024). We execute unit tests to determine the final patch quality.

我们还包含了一个精选的自然语言数据混合，以保留 Devstral-Small 中的通用自然语言理解能力。

We also include a selected mixture of natural language data to retain general natural language understanding capabilities in Devstral-Small.

2.3 后训练 2.3 Post-training

我们采用两阶段训练过程。最初，我们在一个较大的子集上训练模型，这些子集满足我们的第一级质量标准，由启发式过滤器确定。在第二阶段，我们仅使用通过最严格过滤器的轨迹对模型进行微调。

We employ a two-stage training process. Initially, we train the model on a larger subset of rollouts that meet our first level of quality standards, determined by a heuristic filter. In the second stage, we fine-tune the model using only the trajectories that pass our strictest filters.

然后，我们使用微调后的模型进行额外的多轮 rollout，并通过策略优化进一步训练模型。

We then perform additional rounds of rollouts with the finetuned model, and train further the model with policy optimization.

3 实验 3 Experiments

我们展示了 Devstral-Small 在开源模型中取得了最先进的结果（§3.2）。此外，我们进行了进一步分析，以检验迭代评估协议、最大迭代限制以及用于 LLM 采样的温度的影响（见 §3.3）。

We show that Devstral-Small achieves the state-of-the-art result among open models (§3.2). Furthermore, we conduct further analysis to examine the impact of the iterative evaluation protocol, maximum iteration limit, and the temperature used for sampling LLMs (see §3.3).

3.1 设置 3.1 Setup

我们使用智能体式评估设置来评估 Devstral-Small，其中模型可以访问 bash 执行和文件编辑工具。智能体在代码库中探索和编辑代码，模拟人类软件工程师的行为。不使用检索工具或多样本投票。

We evaluate Devstral-Small using an agentic evaluation setup, where the model has access to a bash execution and a file edition tool. The agent explores and edits the code in a code base, mimicking the actions of a human software engineer. No retrieval tool or multi-sample voting is utilized.

我们使用 OpenHands 脚手架（Wang 等人，2025）评估 Devstral-Small。OpenHands 是一个开放平台，旨在开发与人类软件开发人员类似方式与世界交互的 AI 智能体。它提供了一个全面的框架，使智能体能够在安全的沙盒环境中编写代码、与命令行交互以及浏览网页。该平台具有事件流架构，可捕获所有智能体动作和观察结果，从而能够详细分析和改进智能体行为。这使其成为在标准化环境中评估和比较诸如 Devstral-Small 等编码智能体模型的理想脚手架。本文中的所有评估实验均使用 OpenHands（提交号 dc8fc45e94e32498b026a6b6ea91aa0dcb2aa689）进行，以确保可重复性。我们利用 OpenHands 的内置函数调用模板（OpenHands Team，2025b），并禁用函数调用的上下文学习示例。我们在评估期间禁用了 OpenHands 的网页浏览功能。

We evaluate Devstral-Small using the OpenHands scaffold (Wang et al., 2025). OpenHands is an open platform designed to develop AI agents that interact with the world similarly to human software developers. It provides a comprehensive framework that enables agents to write code, interact with command lines, and browse the web within a secure, sandboxed environment. The platform features an event stream architecture that captures all agent actions and observations, allowing for detailed analysis and improvement of agent behavior. This makes it an ideal scaffold for evaluating and comparing coding agent models such as Devstral-Small in a standardized environment. All evaluation experiments in this paper are conducted using OpenHands 111at commit dc8fc45e94e32498b026a6b6ea91aa0dcb2aa689 for reproducibility. We utilize the built-in function calling template of OpenHands (OpenHands Team, 2025b) and disable the in-context learning examples for function calling. We disable the web browsing feature of OpenHands during evaluation.

我们在 SWE-bench Verified（Chowdhury 等人，2024）上进行主要结果和消融实验。我们将 Devstral-Small 与发布时可用的主流开源模型进行比较，均使用 OpenHands 脚手架（OpenHands Team，2025a）。

We perform our main results and ablations on SWE-bench Verified (Chowdhury et al., 2024). We compare Devstral-Small to prominent open-source models available at the time of the release using the OpenHands scaffold (OpenHands Team, 2025a).

为了可重复性，本文报告的结果是使用开源 vLLM（Kwon 等人，2023）框架获得的。我们使用经过分页注意力和自动前缀缓存优化的在线服务器（Kwon 等人，2023）。

For reproducibility, the results reported in this paper are obtained using the open-source vLLM (Kwon et al., 2023) framework. We use the online server optimized with paged attention and automatic prefix caching (Kwon et al., 2023).

我们采用 OpenHands（OpenHands Team，2024）的迭代评估协议，以解决智能体固有的随机性并产生更一致的结果。值得注意的是，即使温度为 0，非确定性来源仍然存在。LLM 后端可能仍会因底层硬件级实现细节（例如 GPU 并行性或浮点舍入差异）而表现出轻微的随机性。此外，智能体运行时效应——例如文件系统状态或元数据（如 mtime（修改时间））的差异——可能导致输入提示因评估执行时间不同而发生变化。这些细微的变化可能导致尽管初始条件看似相同，但输出却不同。

We adopt the iterative evaluation protocol from OpenHands (OpenHands Team, 2024) to address the inherent stochasticity of agents and produce more consistent results. Notably, even with temperature 0, sources of nondeterminism persist. The LLM backend may still exhibit slight stochasticity due to underlying hardware-level implementation details (e.g., GPU parallelism or floating-point rounding differences). In addition, agent runtime effects—such as differences in file system state or metadata like mtime (modification time)—can lead to variations in the input prompt depending on when the evaluation is executed. These subtle shifts can result in different outputs despite ostensibly identical initial conditions.

我们的协议并非多次重复运行同一实例并平均 pass@1 估计值，而是以更少的执行次数实现相当的鲁棒性。对于每个 SWE-bench 实例，我们允许最多 3 次独立尝试生成补丁。每次尝试持续进行，直到智能体以 AgentFinishAction 完成任务或达到迭代限制。第一次尝试使用 temperature=0，我们在第二次和第三次尝试中将其提高到 0.1，以引入受控变化并提高覆盖率。通过聚合最多三次不同的尝试（优先选择后面的解决方案），我们以一小部分计算成本获得了稳定可靠的性能指标。这使得评估过程更加高效和可扩展。我们将更高级的优化策略（例如 Madaan 等人（2023））的探索留给未来工作。

Instead of repeatedly running the same instance many times and averaging pass@1 estimates, our protocol achieves comparable robustness with far fewer executions. For each SWE-bench instance, we allow up to 3 independent attempts to generate a patch. Each attempt proceeds until the agent either completes the task with an AgentFinishAction or hits the iteration limit. The first attempt uses temperature=0, we raise it to 0.1 in the second and third attempts to introduce controlled variation and improve coverage. By aggregating up to three varied attempts (with preference to later solutions), we obtain stable and reliable performance metrics at a fraction of the computational cost. This makes the evaluation process significantly more efficient and scalable. We leave exploration of more advanced refinement strategies (e.g. Madaan et al. (2023)) to future work.

3.3 分析 3.3 Analysis

在本节中，我们进行了一些额外实验，以更深入地了解 Devstral-Small 的行为。具体来说，我们研究了模型在不同展开视野下的表现。此外，我们展示了不同温度下的 pass@N 指标，以提供模型动作空间的视角。

In this section, we conduct some extra experiments to provide more insight into the behavior of Devstral-Small. Specifically, we examine how the model behaves with different rollout horizons. Additionally, we present pass@N metrics at various temperatures to provide a view of the model’s action landscape.

为了理解计算预算如何影响智能体性能，我们在评估过程中检查了不同的最大迭代限制。我们在三种不同约束下评估了模型：30、50 和 100 轮。这些约束代表了每次尝试解决 GitHub 问题时分配的不同计算资源水平。

To understand how computational budget affects agent performance, we examined various maximum iteration limits during evaluation. We assessed our model under three different constraints: 30, 50, and 100 turns. These constraints represent different levels of computational resources allocated to each attempt at solving a github issue.

所有这些实验均在温度 0 下进行，并采用第 3.1 节描述的迭代评估协议。这种设置使我们能够隔离迭代限制对模型性能的影响，同时保持实验条件的一致性。

All these experiments are conducted with temperature 0 and employ the iterative evaluation protocol described in subsection 3.1. This setup allows us to isolate the effect of the iteration limits on model performance while maintaining consistency across experimental conditions.

这些发现表明，对于 Devstral-Small 在软件工程任务上，50 次迭代代表了计算效率与性能之间的最佳平衡。超过 50 次迭代后性能趋于平稳，表明模型通常在此限制内解决问题，或遇到额外迭代无法克服的根本性挑战。

These findings suggest that 50 iterations represent an optimal balance between computational efficiency and performance for Devstral-Small on software engineering tasks. The plateau in performance beyond 50 iterations indicates that the model typically either solves problems within this limit or encounters fundamental challenges that additional iterations cannot overcome.

3.4 温度缩放 3.4 Temperature Scaling

为了研究采样温度对模型性能的影响，我们使用 OpenHands 脚手架进行了全面的温度缩放实验。我们在四种不同温度设置下评估 Devstral-Small：T=0.1、0.4、0.7、1.0，代表了从近乎确定性到高度随机性生成的范围。所有实验均使用最大迭代限制 100，并且不采用迭代评估协议，以隔离温度变化的影响。

To investigate the impact of the sampling temperature on model performance, we conduct a comprehensive temperature scaling experiment using the OpenHands scaffold. We evaluate Devstral-Small across four different temperature settings: T=0.1,0.4,0.7,1.0T=0.1,0.4,0.7,1.0, representing a range from near-deterministic to highly stochastic generation. All experiments use a maximum iteration limit of 100 and do not employ the iterative evaluation protocol to isolate the effects of temperature variation.

我们使用 Pass@K 指标衡量性能，该指标评估模型在至少一次尝试中是否成功。该指标对于理解温度如何影响模型在多次机会下生成成功解决方案的能力尤为重要。

We measure performance using the Pass@K metric, which evaluates whether the model succeeds in at least one of K attempts. This metric is particularly relevant for understanding how temperature affects the model’s ability to generate successful solutions when given multiple opportunities.

图 3 展示了这些结果，清晰地描绘了不同 K 值和温度设置下的性能趋势。该图显示，虽然所有温度设置都实现了相似的 Pass@1 性能（约 43%），但多次尝试（更高 K）的收益随温度变化显著。较低温度下，性能随 K 增加持续提升，而较高温度则表现出更不稳定的性能模式。这些结果与直觉相反，因为通常预期较高温度会随 K 更好地缩放，正如竞争性编程练习中的情况。

Lower temperatures consistently improve with increased K, whereas higher temperatures display more volatile performance patterns. These results are counter-intuitive, as higher temperatures are expected to scale better with K, as is the case for competitive programming exercises.

4 刷新 Devstral-Small 数据 4 Refreshing Devstral-Small Data

在发布第一代 Devstral-Small 后，我们通过改进数据集开发了更新版本。我们通过仔细的消融研究，精心优化了数据生成和筛选过程。为了提高对不同脚手架的泛化能力，我们创建了多种伪脚手架。我们的训练包括 XML 和原生函数调用格式的提示。此外，我们微调了数据过滤机制以确保高质量轨迹选择，这有助于校准第一阶段数据（如第 2.3 节所述）。

After releasing the first generation of Devstral-Small, we developed an updated version by improving our dataset. We meticulously refined the data generation and curation process through careful ablation studies. To improve generalization to diverse scaffolds, we created a variety of pseudo-scaffolds. Our training included prompts in both XML and our native function calling formats. Furthermore, we fine-tuned the data filtering mechanism to ensure high-quality trajectory selection, which helped calibrate the first-stage data (as described in Section subsection 2.3).

5 结论 5 Conclusion

在本技术报告中，我们介绍了 Devstral-Small，一个用于智能体式编码的高性能开源模型。它仍然是其权重类别中最好的模型，是低于 100B 参数的最强模型，且易于在设备上部署。

In this technical report, we introduce Devstral-Small, a high-performance open-source model for agentic coding. It remains the best of its weight class, being the most capable model below 100B parameters and easily deployable on device.

Devstral-Small 是一个轻量级 24B 模型，它学会了使用脚手架来检查、编辑、增强和修复代码库中的代码片段。它速度快，可在本地设备上部署。

Devstral-Small is a lightweight 24B model, which learned to use scaffolds to inspect, edit, enhance, and fix code segments within code bases. It is fast and deployable on local devices.
