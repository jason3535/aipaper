十二个月内大语言模型的三个拐点

Three LLM inflection points in twelve months

西蒙·威利森 Simon Willison · 2026-11-24 · Article ↗

摘要 · Abstract

本文考察了截至 2026 年 11 月的十二个月内，大语言模型与编程智能体能力上的三个重要拐点。第一个是 2025 年 11 月发布的 Claude Opus 4.5，它使 Claude Code 和 OpenAI 的 Codex 等编程智能体在日常开发工作中变得可靠实用。第二个是作者所称的 Fable 类模型的出现，始于 2026 年 6 月的 Claude Fable 5，其定义性特征是：只需给模型一个目标和合适的工具，就能看它完成工作；这类模型如今已成为前沿模型的基线预期。第三个是能够理解趣味、并产出真正引人入胜的游戏之模型的出现，最早见于 2026 年 9 月的 Claude Opus 5.5，作者将其与围绕 AI 辅助游戏开发的更广泛文化之争联系起来。作者总结道，软件开发已发生翻天覆地的变化，他很可能再也不会回到手敲大部分代码的状态，而 Fable 5.2 或许代表又一个拐点——清晰描述的软件可以直接被构建出来。

This article examines three significant inflection points in the capabilities of large language models and coding agents over the twelve months preceding November 2026. The first was Claude Opus 4.5, released in November 2025, which made coding agents like Claude Code and OpenAI's Codex reliably useful for everyday development work. The second was the arrival of what the author calls Fable class models, beginning with Claude Fable 5 in June 2026, defined by the ability to give a model a goal and the right tools and watch it complete the work; these now set the baseline expectation for frontier models. The third was the emergence of models that understand fun and produce genuinely engaging games, first observed with Claude Opus 5.5 in September 2026, which the author links to a broader culture war over AI-assisted game development. The author concludes that software development has transformed beyond recognition, that he will likely never return to typing most of his code by hand, and that Fable 5.2 may represent a further inflection point in which clearly described software can simply be built.

核心贡献 · Key contributions

  • 指出 Claude Opus 4.5（2025 年 11 月）是首个让编程智能体在日常开发中可靠可用的模型。
    Identifies Claude Opus 4.5 (Nov 2025) as first model making coding agents reliably useful for everyday development.
  • 定义 Fable 类模型：给定目标与工具，即可观察模型自主完成工作。
    Defines Fable class models: give a goal and tools, then watch the model complete the work autonomously.
  • 指出前沿大模型在四个月内于 3D 建模与空间感知方面显著变强。
    Notes frontier LLMs became notably strong at 3D modeling and spatial awareness within four months.
  • Claude Opus 5.5 首次表现出理解趣味性，通过试玩将乏味游戏变得引人入胜。
    Claude Opus 5.5 first appeared to understand fun, turning dull games into engaging ones via playtesting.
  • 认为软件开发已面目全非，作者不再手写大部分代码。
    Argues software development transformed beyond recognition; author no longer types most code by hand.
  • 提出 Fable 5.2 或标志新拐点：清晰描述的软件即可被直接构建。
    Suggests Fable 5.2 may mark a further inflection point where clearly described software is simply built.

局限 · Limitations

  • 证据多来自单一开发者的轶事经验，而非系统基准或受控研究。
    Evidence is largely anecdotal from one developer's experience, not systematic benchmarks or controlled studies.
  • Fable 类定义非正式且主观，缺乏精确能力阈值或评估标准。
    Fable class definition is informal and subjective, lacking precise capability thresholds or evaluation criteria.
  • 模型可用性受出口管制干扰，引发治理与访问边界问题。
    Model availability was disrupted by export controls, raising governance and access-boundary concerns.
  • 趣味与品味判断主观，模型是否理解趣味仍难以验证。
    Fun and taste judgments are subjective; claims of model understanding fun remain hard to verify.
  • Fable 5.2 是真正拐点还是渐进改进，作者本人仍未定论。
    Whether Fable 5.2 is a true inflection point or incremental improvement remains undecided by the author.

十二个月内 LLM 的三个拐点 Three LLM inflection points in twelve months

几周前，我在 AI Engineer Code Summit 上做了一场主题演讲，演讲围绕这样一个观点展开：在过去十二个月里，LLM 与编程智能体的能力出现了三个重要的拐点。

I gave a keynote at the AI Engineer Code Summit a couple of weeks ago, constructed around the idea that there have been three significant inflection points in the abilities of LLMs and coding agents in the past twelve months.

这里是演讲视频。在本文中，我将提炼出“拐点”这一核心主题，并对其进行更深入的审视。

Here's the video of the talk. In this post I'm going to pull out the major inflection point theme and interrogate it more deeply.

2025 年 11 月的编程智能体 Coding agents in November 2025

今天是 2026 年 11 月 24 日，正值 Claude Opus 4.5 发布一周年。事后看来，这是一个具有重大影响的模型。

Today, November 24th 2026, is the one year anniversary of the release of Claude Opus 4.5. With hindsight, this was a consequential model.

在 Opus 4.5 的发布公告中，Anthropic 表示：

In the Opus 4.5 announcement, Anthropic said:

测试者指出，Claude Opus 4.5 能够处理模糊性并权衡取舍，而无需手把手指导。他们告诉我们，当面对一个复杂的多系统缺陷时，Opus 4.5 能够找出修复方案。他们表示，就在几周前对 Sonnet 4.5 来说几乎不可能完成的任务，如今已触手可及。

Testers noted that Claude Opus 4.5 handles ambiguity and reasons about tradeoffs without hand-holding. They told us that, when pointed at a complex, multi-system bug, Opus 4.5 figures out the fix. They said that tasks that were near-impossible for Sonnet 4.5 just a few weeks ago are now within reach.

当时 Claude Code 已问世 9 个月，它于 2025 年 2 月 24 日与 Claude 3.7 Sonnet 一同推出。

Claude Code was 9 months old at that point, having been introduced alongside Claude 3.7 Sonnet on February 24th, 2025.

Opus 4.5 是我在 Claude Code 中使用过的第一个默认结果通常就是正确做法的模型。此前我并未将 Claude Code 作为日常主力工具，因为它感觉不够可靠——我需要频繁纠正它，以至于它算不上明显的加速器。

Opus 4.5 was the first model I had used with Claude Code where the default result was generally the right thing. I hadn't been using Claude Code as a daily driver because it didn't feel reliable enough—I had to correct it often enough that it didn't feel like a clear accelerant.

新的 Opus 改变了这一点。对于我日常面对的大多数编程问题，Opus 都能**把它们做对**。它显然比我自己逐一解决这些问题要快。

The new Opus changed that. For most of the coding problems I faced on a daily basis, Opus would _get them right_. It was clearly faster than working through the problems myself.

同样在 11 月，OpenAI 发布了 GPT-5.1 Instant、GPT-5.1 Thinking、GPT-5.1-Codex 和 GPT-5.1-Codex-Max。这些模型对其 Codex 编程智能体产生了类似的效果：对于我的许多编程任务，它变得可靠且实用。

Also in November, OpenAI released GPT-5.1 Instant, GPT-5.1 Thinking, GPT-5.1-Codex, and GPT-5.1-Codex-Max. These had a similar effect on their Codex coding agent: it became reliably useful for many of my coding tasks.

时机很凑巧，因为 12 月的假期即将到来。包括我在内的许多人，整个 12 月都在摆弄这些新工具，看看它们能做什么。到 1 月，我们已经准备好将它们用于实际工作了。

The timing was convenient, because the December holidays were upon us. A lot of people, myself included, spent December tinkering with these new tools to see what they could do. By January we were ready to use them for our actual work.

六/七月的 Fable 级模型 Fable class models in June/July

我们在四月首次得知 Claude Fable 的线索，当时 Anthropic 发布了 Claude Mythos，并表示由于其网络安全能力的提升，该模型 _过于危险_ 而不宜发布。Mythos 不仅能发现安全漏洞，还能找出如何利用这些漏洞。

We got our first hint of Claude Fable in April, when Anthropic announced Claude Mythos and said that it was _too dangerous_ to release, due to its improved cybersecurity capabilities. Mythos was a model that could not just find security vulnerabilities, it could also figure out how to exploit them.

六月，随着 Claude Fable 5 的发布，我们亲眼见识了该模型的能力——一个被去除了危险功能的 Mythos，它能解决大多数问题，但会主动阻止你将其用于安全工作。

In June we got to see how good that model was for ourselves, with the release of Claude Fable 5—a defanged Mythos, that would solve most problems but would actively block you from using it for security work.

经过辉煌的三天……美国政府将其从我们手中夺走。Fable 5 被置于出口管制之下，实际上禁用了该模型。直到 7 月 1 日我们才重新获得它。

After three glorious days... the US government took it away from us. Fable 5 was placed under export controls that effectively banned the model. We wouldn’t get it back until July 1st.

对我而言，Fable 是一个转折点，因为它向我们介绍了我现在称之为 **Fable 级模型** 的概念。我对这些模型的定义是：

For me, Fable was an inflection point because it introduced us to what I now think of as **Fable class models**. My definition of these:

给它一个目标，给它合适的工具，然后看它大显身手。

Give it a goal, give it the right tools, and watch it cook.

我目前会将 Claude Fable 5、5.1、5.2 以及 Claude Opus 5.5 归为 Fable 级（我把 Opus 5.5 视为“廉价版 Fable”）。GPT-6 Astra 在我看来也达到了这一水平，而且我认为新的 Gemini 4 Neon 或许也能算在内。

I would currently class Claude Fable 5, 5.1, 5.2 and Claude Opus 5.5 as Fable class (I think of Opus 5.5 as "cheap Fable"). GPT-6 Astra got there for me too, and I think the new Gemini 4 Neon may count as well.

这些模型如今构成了我对前沿模型所应达到水平的基线。

These now represent the baseline for what I expect from a frontier model.

9 月/10 月的 3D 建模与游戏开发 3D modeling and game development in September/October

过去仅仅四个月里，前沿模型（frontier model）身上发生了一件有趣的事：它们在 3D 建模方面变得**非常出色**。给它们配上 Blender，或者让它们编写 Three.js 代码，它们就能为你要求的几乎任何东西生成可信的模型。

Something interesting happened with frontier LLMs over just the past four months: they got _really good_ at 3D modeling. Set them up with Blender or ask them to write Three.js code and they'll produce credible models of almost anything you ask for.

我最早是在 Claude Fable 5 上注意到这一点的，但真正开始发力是在 Opus 5.5、GPT-5.6 Sol、GPT-6 Astra，以及最近的 Gemini 4 系列上。例如，下面是 Gemini 4 Neon 对“制作一个 three js 动画：yonkers 站起来变成一个大型机甲（酷炫的站起动作），在曼哈顿、皇后区和布鲁克林跺脚行走，使用 openstreetmap 地图数据”这一提示的尝试。

I first noticed this with Claude Fable 5, but it really kicked into gear with Opus 5.5, GPT-5.6 Sol, GPT-6 Astra, and most recently the Gemini 4 family. Here's Gemini 4 Neon's attempt at "Make a three js animation where yonkers stands up as a big mech (cool stand up motion) and stomps around manhattan and queens and Brooklyn, use openstreetmap mapping data", for example.

如果你想将视觉 LLM 用于机器人领域，3D 空间感知至关重要。我不知道 3D 建模能力是各实验室专注于此的副产品，还是反过来。

3D spatial awareness is crucial if you want to use vision LLMs for robotics. I don't know if 3D modeling capabilities are a side-effect of the labs focusing on that or vice-versa.

早在八月，我就尝试让 Fable 5 为我构建一个浣熊抢劫游戏。它有 3D 图形，看起来像一款游戏，但玩起来非常糟糕。GPT-5.6 Sol Ultra 做得要好得多，但游戏本身在最初 90 秒的游玩之后仍然相当乏味。

Back in August I experimented with having Fable 5 build me a raccoon heist game. It had 3D graphics, looked like a game, and played really poorly. GPT-5.6 Sol Ultra did a much better job but the game itself was still pretty dull after the first 90 seconds of play.

让我稍感宽慰的是，设计一款**有趣**的游戏似乎仍然是人类独有的追求。我甚至在九月的一次演讲中引用了这一点，来安抚人们：我们人类仍然有可以扮演的角色！

I was somewhat relieved that designing a game that was _fun_ appeared to remain a uniquely human pursuit. I even used that in a talk in September to reassure people that us humans still had a role to play!

然后，我试着告诉 Claude Opus 5.5：“这个游戏还不够有趣。让它变得有趣得多。”结果奏效了。我的《命令与征服》风格 RTS 在一夜之间从无聊变得极具娱乐性，因为 Opus 花了 12 个小时试玩新功能并重新平衡游戏玩法。

Then, I tried telling Claude Opus 5.5 “This game isn’t fun enough yet. Make it a LOT more fun.” And it worked. My Command & Conquer-style RTS went from boring to deeply entertaining overnight, after Opus spent 12 hours playtesting new features and rebalancing the gameplay.

Opus 5.5 是我用过的第一个似乎理解“趣味”的模型。此后，我参与了好几个小型游戏项目，像“认真思考如何确保它既有趣又美观”这样的提示词产生的结果让我投入了相当长的时间。

Opus 5.5 was the first model I’d used that appeared to understand fun. I’ve since worked on several little game projects where prompts like “Think hard about how to make sure it is both fun and beautiful” produced results that kept me engaged for significant amounts of time.

Opus 5.5 于 2026 年 9 月 22 日发布。此后我参加了两个不同的会议，人们向我展示了他们一直在做的游戏项目，这些项目确实感觉像是正经的、值得玩的游戏。

Opus 5.5 came out on September 22nd, 2026. I’ve been to two different conferences since then where people showed me game projects they’d been working on that really did feel like proper, worthwhile games.

独立游戏界因 AI 辅助编程陷入了一场全面的文化战争。很多人称《GTA VI》是最后一款前生成式 AI 时代的大作。

The indie games scene has descended into a full-blown culture war over AI-assisted programming. A lot of people are calling GTA VI the last pre-generative AI blockbuster.

对我来说，这感觉像是另一个拐点。

It feels like another inflection point to me.

Fable 5.2 也是一个拐点吗？ Is Fable 5.2 an inflection point too?

我仍在试图判断 Fable 5.2 是代表一个新的拐点，还是仅仅是又一次渐进式改进。

I’m still trying to decide if Fable 5.2 represents a new inflection point, or just another incremental improvement.

我现在用那个模型完成了 _如此多_ 的工作！

I’m getting _so much_ done with that model right now!

它的品味似乎几乎与我完全匹配。我一直在解决各种棘手的问题，这些问题我已经思考（或拖延）了好几年。Datasette 1.0a42、1.0a43 和 1.0a44 的发布说明——加上 LLM 0.37、0.37.1、0.37.2、0.37.3 和 0.38——_全部在过去的三个星期内_，代表了大量修复、功能和改进的涌现。

It seems to have taste that almost exactly matches my own. I have been burning through all sorts of gnarly problems that I’ve been thinking about (or procrastinating on) for several years now. The release notes for Datasette 1.0a42, 1.0a43, and 1.0a44—plus LLM 0.37, 0.37.1, 0.37.2, 0.37.3, and 0.38—_all in the last three weeks_, represent a flood of fixes, features and improvements.

如果这确实代表一个拐点，关键特征似乎是 _如果你能想象并清晰地描述一个软件，Fable 就能构建它_。这样说很疯狂，但它与我过去几周的经历相符。

If this does represent an inflection point, the key feature seems to be that _if you can imagine and then clearly describe a piece of software, Fable can build it_. That’s a wild thing to say, but it matches my experience over the past few weeks.

软件开发在过去一年里发生了翻天覆地的变化。我认为我再也不会回到手动输入大部分代码的状态了。

Software development has transformed beyond recognition in the last year. I don’t think I’ll ever go back to typing most of my code by hand.
